# Behavioural quality — tt-tnt-v1-vs-v3

Baseline `artifacts/hf-tt-tnt-v1` (tt-tnt-v1) vs candidate `artifacts/hf-tt-tnt-v3` (tt-tnt-v3). 32 and 32 completions per prompt respectively, over 15 shared prompts. Generated by `scripts/score_behaviour.py --compare`.

## Method, in brief

- **Paired by prompt.** Both runs answered the same frozen prompts, so the difference is computed within each prompt and averaged over prompts. That removes between-prompt variance, which is most of the variance here.
- The `difference` column is `candidate - baseline`, mean ± SEM **over prompts**, with its 95% interval. A difference whose interval spans zero is reported as **no change** -- not as a small improvement.
- `better` states which direction counts as an improvement for that signal, so a regression is reported as a regression.
- `min. detectable` is `1.96 × SEM` of the difference: the smallest change this comparison had the power to call. Read every **no change** verdict against it -- a null result only means "nothing there" for effects larger than that number.

## Validation: does this metric agree with what we already knew?

`tt-tnt-v3` is the better model, established independently of anything here: hand-counted genre
collapse 9/15 vs 1/15, termination 5/15 vs 0/15, like-for-like loss ~2.99 vs ~3.19, and the
context-use probe. A metric that could not reproduce that ranking would be a vanity metric, so
this is the acceptance test for the tool, not for the model.

**It reproduces the ranking on the two signals the prior evidence actually established, and it
took one correction to get there.**

| prior finding | how it was established | what this metric says |
|---|---|---|
| v3 terminates, v1 never does | hand count, 5/15 vs 0/15, CPU greedy | **confirmed, decisively.** 0.000 ± 0.000 vs 0.144 ± 0.053; v1 emitted `</s>` on **0 of 480** completions |
| v3 collapses into TinyStories far less | hand count, 9/15 vs 1/15, CPU greedy | **confirmed** on story-frame collapse, 0.133 → 0.050 |
| v3 has lower loss on a like-for-like yardstick | `scripts/eval_per_source.py` | out of scope here (this tool does not measure loss) |

### The correction, stated plainly

The collapse detector was first built as a single union of eleven TinyStories markers, and in
that form it said v1 and v3 collapse at **indistinguishable** rates — flatly contradicting the
hand count. The per-marker breakdown said why:

| marker | v1 (of 480) | v3 (of 480) |
|---|---:|---:|
| `once_upon_a_time` | 10.8% | **0.0%** |
| `little_X_named` | 8.3% | **0.4%** |
| `one_day_comma` | 14.8% | 12.5% |
| `so_very_happy` | 7.9% | 10.2% |
| `named_proper` | 15.0% | 7.1% |
| `his_her_mom` | 4.0% | 4.8% |

The *story frame* — the formulaic opening, closing, and moral a human counts when reading
samples — very nearly vanished between the two models. The *lexical habits* did not move. The
union averaged a large real effect against a null one and reported the average.

So the signal was split in two (`FRAME_MARKERS` / `LEXICAL_MARKERS`), by what each marker **is**,
with the original union retained unchanged beside them. This split was made after seeing the
disagreement, which is worth saying out loud: judge it by reading the two marker lists and the
per-marker control table in `behaviour-tt-tnt-v3.md`, not by trusting that it was principled.

### Where this metric disagrees, and which side to believe

**The register signal says v1 and v3 write in the same register**, and it is not close to
significant: `nearest source == tinystories` is 0.525 for both models (difference 0.000 ± 0.038),
and the tinystories margin moves −0.035 ± 0.091 nats/word.

We believe the measurement, for three reasons.

1. **It is not contradicted by anything.** None of the prior conclusions established a register
   improvement. Collapse (hand-counted) was counted on frame phrases, and this metric agrees
   about those. Loss and context use are not register claims. There is no prior finding here to
   overturn — only an expectation.
2. **A second, independent detector says the same thing.** The lexical-habit sub-signal is a
   hand-written regex list; the register model is a corpus-fit unigram+bigram likelihood. They
   share no code and no design. Both say v3's *vocabulary* is as TinyStories-flavoured as v1's.
3. **The register signal is not simply blind.** Its controls (`behaviour-tt-tnt-v3.md`) show
   99.9% accuracy separating held-out `tinystories` from the other eight sources at completion
   length, and its per-prompt values in this very run span −0.77 to +2.03 nats/word. It has the
   dynamic range to see a change; there was not one to see.

The honest reading of the pair, then: **`tt-tnt-v3` stopped writing fairy tales but did not stop
using fairy-tale words.** That is a narrower improvement than "collapse went from 9/15 to 1/15"
suggests on its own, and it is a specific, actionable target for the next run.

### Can this metric say a model got worse?

It must be able to, or it is a scoreboard rather than a measurement.

- The verdict logic reports **worse** whenever a difference's 95% interval excludes zero in the
  bad direction, per-signal, using each signal's own declared direction.
  `tests/test_score_behaviour.py::test_a_clear_regression_is_reported_as_worse` and
  `::test_a_regression_on_a_higher_is_better_signal_is_also_worse` pin that, and reverting the
  verdict logic so it can never say "worse" fails four tests.
- On this pair, **three of nine signals moved in the wrong direction** — 4-gram repeat rate
  (+0.006), longest repeated span (+0.14), prompt engagement (−0.034) — and the tool names them
  under the verdict rather than burying them. None crosses significance, so none is reported as
  a regression.
- Worth watching: the repetition regression is if anything *understated*. v3's completions are
  shorter (55.8 vs 60.0 tokens, because it terminates), and shorter completions have fewer
  chances to repeat — yet v3's repeat rate is still the higher of the two.

### Robustness check (not committed as a measurement)

Both models were also scored at `--temperature 0.3`, nearer the greedy regime the original hand
count used. The story-frame effect is the same size or larger there (−0.108 ± 0.060 vs
−0.083 ± 0.042) but noisier, because low-temperature completions are more alike and degenerate
looping dominates (4-gram repeat rate ≈ 0.31 for *both* models at T=0.3, against ≈0.03 at T=0.8).
Termination still separates cleanly (0.000 → 0.210). Register still shows no improvement, and at
T=0.3 it drifts in the *wrong* direction (`nearest == tinystories` +0.075). Nothing in the
conclusions above depends on the sampling temperature.

### Power, and why more samples will not help much

`min. detectable` above is the smallest effect this comparison could have called. At n=15 prompts
× 32 completions, story-frame collapse is right at the edge (effect −0.083, minimum detectable
0.081). The obvious response — draw more completions per prompt — barely helps. Decomposing the
observed paired SEM into the within-prompt sampling noise (recoverable from the per-prompt SEMs
both runs record) and the residual prompt×model variation:

| signal | paired SEM | of which sampling noise | of which prompt×model | projected SEM at 64 samples |
|---|---:|---:|---:|---:|
| story-frame collapse | 0.0416 | 0.0152 | 0.0387 | 0.0401 |
| genre collapse (any) | 0.0306 | 0.0215 | 0.0218 | 0.0265 |
| termination rate | 0.0532 | 0.0134 | 0.0515 | 0.0524 |
| nearest == tinystories | 0.0383 | 0.0226 | 0.0310 | 0.0348 |

Doubling the completions per prompt buys 3–13%. The binding constraint is the **15 frozen
prompts**, not the samples drawn from them. The prompt set is deliberately frozen for cross-checkpoint
comparability, so the right way to buy power is a *second* frozen set with new ids, sized for
this purpose and reported separately — never by editing this one.

**That set now exists**: `docs/evaluation_prompts_b.json` (set B, 45 prompts, digest-pinned by
`tests/test_evaluation_prompts_b.py`), scored with `scripts/score_behaviour.py --prompt-set b`
and written to `behaviour-<label>-setB.{md,json}`. The two sets are reported side by side and
never pooled; `--compare` refuses to pair runs from different sets. On the same paired-SEM basis
as the table above, 45 prompts take story-frame collapse's minimum detectable effect from 0.081
to **0.047** — *if* set B's prompts differ between checkpoints as much as set A's did. They may
not: set A's whole −0.083 comes from three prompts (71% of it from two) and v3 is at exactly
0.000 on 12 of 15, and adding prompts on which both models score zero shrinks the effect and the
SEM at the same rate, leaving |t| unmoved. Prompts on which the models *differ* are what buy
power; prompts alone are not. See the CLAUDE.md entry for the full arithmetic.
