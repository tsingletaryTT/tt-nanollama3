# External benchmarks — `gpt2`

Model `/home/ttuser/code/tt-tnt/scratch/hf-gpt2`, evaluated on CPU by EleutherAI's `lm-evaluation-harness` 0.4.9 at a 1024-token context, dtype float32, batch size 16. Generated by `scripts/benchmark_external.py`.

## Why this exists

**This is a reference run, not a measurement of one of our models.** It exists so that the GPT-2-small column in this project's own external-benchmark reports is a *measured* head-to-head — same harness version, same task definitions, same machine, same day — instead of a figure quoted from a paper that used different detokenizers and different scoring code. Feed this file to `scripts/benchmark_external.py --reference-json`.

The chance-baseline labelling rule is applied here unchanged. GPT-2 small is also at chance on several of these tasks, and that is exactly the context a reader needs: it is not only *our* model that cannot do them.

## How to read this table

- **chance** is what a model that had learned nothing would score. For 4-way multiple choice that is 0.25; for 2-way, 0.50; for open-vocabulary last-word prediction it is ~1/32000, i.e. zero. Perplexities have no chance baseline — there is no "guess at random" strategy for them — and are reported directly.
- **verdict** applies one rule: a score within **2 standard errors** of chance is `AT CHANCE`, and `AT CHANCE` means the number in the score column **is not a measurement of this model**. It is printed so you can see what was suppressed and check the arithmetic, not so it can be quoted. In the companion JSON such a row has `reportable_score: null`.
- This mirrors `scripts/evaluate.py`, which labels any delta inside ~1.2x of the seed-noise floor `NOT INTERPRETABLE` no matter what its confidence interval says. Same principle, different null: there, another run of the same recipe; here, a model that learned nothing.
- **stderr** is lm-eval's own standard error over benchmark items. It covers sampling of the benchmark, and nothing else — not training-seed variance, not prompt-format sensitivity. It is a lower bound on the real uncertainty.
- **The gate is applied per row, and this table has 11 of them.** If every one of those scores were truly at chance, roughly **0.5** would still clear a 2-standard-error gate by luck alone. A row sitting just past the threshold is therefore weaker evidence than its verdict makes it look; a row at 5+ standard errors, or a pattern of several rows moving the same way, is not.

## Did the context window truncate anything?

This model's window is **1024 tokens**. When a prompt plus its continuation exceeds it, lm-eval drops tokens off the **front of the context** and the model answers a question it was only shown part of. Every request the harness actually issued was re-tokenized with this model's own tokenizer and checked against the limit.

## Caveats on the GPT-2 column

- Published figures were produced by their authors' own code, not by lm-eval. Task definitions, detokenizers and normalisation all differ in detail, so treat a published row as an order-of-magnitude reference and not as a head-to-head result.
- `wikitext` word perplexity: The paper applies invertible detokenizers before scoring and normalises by its own word count; lm-eval's word_perplexity uses a different detokenizer and word count, so the two are close in spirit and not identical in protocol.
- `lambada_openai` last-word accuracy: The paper's LAMBADA accuracy uses a stopword filter on generation; lm-eval's lambada_openai scores the exact continuation by loglikelihood, which typically reads lower (~0.33 for gpt2 in lm-eval).

- Verified at run time: the `wikitext-2-raw-v1` and `wikitext-103-raw-v1` test splits are byte-identical (1,288,493 characters), so lm-eval's `wikitext` task reports WikiText-103 test perplexity.

The harness lives in a throwaway virtualenv under `scratch/` (gitignored) and `scripts/benchmark_external.py` shells out to it.

- `torch`: 2.7.0+cpu
- `transformers`: 4.55.4
- `datasets`: 5.0.1
- device: `cpu` (CPU-only by design; this script refuses any other device and never opens a Tenstorrent device)
